## Data availability — and one important gap

**The observed sets `A(I)` are not stored anywhere in the repository.** The
instance files hold only CNF clauses (by design, documented in
`generate_instances.py`), and the result files hold only derived summaries:
`data/phase2/part10_results.json → per_instance_summary` carries
`(id, n, alpha, regime, S_I_size, A_I_size, eps_hat, is_fragmented, max_excess_components)`
for 349 instances. A grep for stored assignment vectors across `data/` returns nothing.

**This did not force a fresh reproduction.** Stage A is deterministic —
`rng = np.random.default_rng(STAGE_A_SEED + rec["id"])` per instance — so `A(I)`
is exactly regenerable, and it was regenerated by importing the repository's own
WalkSAT unchanged. The regeneration reproduces the published `A_I_size`, `S_I_size`
and `eps_hat` exactly (verified on every one of the 349 instances; see
`data/validate_all349.csv`). **Therefore this is a reproduction of the published
experiment, not merely a fresh reproduction of its design.** The only caveat is
NumPy's generator stream, which is relied upon and is confirmed stable: the
published values reproduce under NumPy 2.5.4 although the paper used 1.26.4.

## Tooling limitation, recorded

`drat-trim` was **not** used. Downloading and compiling third-party C source was
declined by this environment's policy, and no DRAT/LRAT checker was installed.
Independently checked upper bounds therefore come from two routes written for this
audit instead: `src/drup.py`, a self-contained forward RUP checker, and exhaustive
enumeration for `n ≤ 24`. `src/drup.py` is my own code and has not been
cross-validated against an established checker — that is a real limitation and is
carried into `CLAIMS.md`. It was shown to reject a tampered proof, and it agrees
with the exhaustive route on every instance where both ran.
